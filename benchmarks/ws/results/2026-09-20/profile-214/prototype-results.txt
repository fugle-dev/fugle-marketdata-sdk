Prototype: core keeps `data` of a data event as the verbatim JSON slice (serde_json RawValue) instead of
parsing it into a serde_json::Value tree (preserve_order = IndexMap) that JS and Python never read and
UniFFI only re-serialises into `data_json`. Patch: prototype-data-rawvalue.patch (measurement only, not
shipped: it adds a public field to core::WebSocketMessage and leaves `data` empty for data events).

Same machine, same evening, 3 runs each, medians; baseline = cpu-rerun/ (main f7c31e7 tree).

System CPU rises under the prototype in every case (10K: +5-7 ms; 50K: +13-22 ms), so user+system only
drops 1.5-4% at 10K and 4-10% at 50K. The prototype runs' per-run JSON was not kept (ws-bench-run.js
overwrites ws-benchmark-results.json); the medians above are what was recorded.

A first prototype that dropped `data` entirely (IgnoredAny) measured Go 108 / 218 ms and C# 120 / 252 ms,
but those numbers are invalid: the Go/C#/Java bench clients read `dataJson`, which that prototype left
null, so the clients skipped their own JSON parse. Only the RawValue variant above is a fair comparison.
